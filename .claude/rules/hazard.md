# ハザード評価の注意

CLAUDE.md の「実装上の注意」から領域別に分けたもの（→ CLAUDE.md の表）。
実際に踏んだ落とし穴なので、該当する処理を書く・直す前に読む。

- ⚠⚠ **ハザード評価は「区域外（`value=0`）」と「未解決（行が無い）」を混ぜない**
  （→ ADR 0021・課題#46）。混ぜると**「危険なのに情報が無いから減点されない」掲載が
  「安全」と同じ扱いになり、例外にならないまま順位が狂う**。
  ⚠ **`float(value or 0)` と書かない**（0.0 は falsy なので未解決に化ける）。
  担保は生成の恒等式 assert・読み込みの検証・採点（0.0 は満点の hit / None は
  `missing` で分母から除外）の3層
- ⚠⚠ **液状化は「危険ランク」で持つ（`rank = 6 − 原典のレベル`）**（→ ADR 0023・課題#59）。
  原典は「小さいほど危険」で既存のハザードと**向きが逆**なので、**生成の1箇所で反転**して
  構造的に潰してある。⚠ **`best` は 0 ではなく 1**（丁目の全面が「液状化しにくい」）。
  ⚠ 重ねるハザードマップと比べるときは **`6 − rank`** で原典のレベルへ戻す。
  ⚠⚠ **原典の「レベル6」は評価対象外（湖沼・河道）であって「安全」ではない**——
  分子にも分母にも入れない。実測で108丁目に混ざり、我孫子市我孫子新田では
  混ぜると 4.265 → **2.292** と1.97も甘くなる（手賀沼の水面を「安全」と数える）。
  ⚠ **分母は丁目の全面積ではなく「評価対象の面積」**（液状化は全面にレベルが付くので
  「区域外」が存在しない）。⚠ **売買4本にだけ配点する**——ゲートが**母集団で割れた**
  （丁目単位 −0.560 に対し、実際の掲載では賃貸2帯が **+0.767 / +0.698** で不通過）
- ⚠⚠ **ハザードのタイル集合は丁目境界の bbox から導く。矩形で決め打ちしない**
  （→ 課題#59）。4都県の外接矩形には**島嶼部（小笠原・大島・八丈島など404丁目）が
  入らず**、矩形で取ると恒等式を満たせないまま「取れたつもり」になる。
  ⚠ **ベクトルタイルの geometry をそのまま使わない**——タイル境界で切り取られ（3.4%）、
  しかもバッファで隣接タイルへはみ出す（最大 0.7725″）。`mesh_code` から矩形を
  再構成する（満寸の geometry 70,228件と一致・最大ずれ 0.077″）。
  ⚠ **幅が2種類あるのは量子化**（z11 の 632.8″ ÷ 4096）なので断片と誤判定しない
- ⚠⚠ **`build_hazard_levels.py` の中間キャッシュはデータセット別**（→ 課題#59）。
  1ファイルにまとめると `--datasets xkt025` の単独実行で洪水・土砂の交差が消え、
  続く `--from-cache` で**洪水が全件0（＝「区域外と確認」）に化ける**（例外にならない）
- **ハザードは丁目で引き、無ければ `m_address_points.town_key` 経由で町へ落とす。**
  ⚠ **SQL の文字列操作で「N丁目」を剥がさない**（丁目の無い町で番地を削り別の町を指す →
  ADR 0020 と同じ失敗）。⚠ **ハウスコムは住所が町名までしか無い**ので、
  この経路が無いとそのサイトの掲載が丸ごと未解決になる
- ⚠ **ハザードの丁目照合に「代表点がポリゴン内か」を使わない。** 実測で
  **12分の1しか拾えない**（東京都のA33で代表点80丁目 vs 交差判定1,140丁目）。
  ⚠ **例外にならず静かに過小評価される。** 丁目境界ポリゴンとの交差で判定する。
  ⚠ ハザード側の所在地属性（A33_006）で代替するのも誤り（A31 に住所属性が無く、
  A33 も県によって欠損する）
- ⚠ **洪水と土砂で集計方式を分ける。** 該当する丁目は洪水72.9% / 土砂18.9% と
  分布が正反対で、1つの方式では両方に判別力を出せない。
  ⚠ **23区は3,124丁目のうち浸水想定に一切掛からないのが2丁目だけ**なので、
  面積比は判別力を持たない（浸水深の面積加重平均を使う）。
  ⚠ **最大ランクは外れ値に引っ張られる**（水路際のランク6がごく一部でも丁目全体が最悪扱い）
