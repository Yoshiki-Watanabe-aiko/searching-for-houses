# ハザード評価（丁目・町単位）

`hazard_levels.csv` は `m_hazard_levels` の正典。洪水と土砂災害の危険度を
**丁目（一部は町）の単位**で持つ（→ [課題#46](../../docs/課題管理表.md)）。

## 出典

- 「国土数値情報（洪水浸水想定区域データ A31・想定最大規模）」（国土交通省）
  <https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A31-v4_0.html>
- 「国土数値情報（土砂災害警戒区域データ A33）」（国土交通省）
  <https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A33-v1_4.html>
- 「令和2年国勢調査 町丁・字等別境界データ」（総務省統計局・e-Stat）
  <https://www.e-stat.go.jp/gis>

上記をもとに丁目境界との交差面積を計算して作成した。

⚠ **A33 の利用条件**: 対象4都県（東京都・埼玉県・千葉県・神奈川県）はいずれも
「オープンデータとしての利用可（商用利用可・再配信可）」に含まれる。
⚠ **e-Stat の境界データ**: 政府標準利用規約（第2.0版）。

## 作り方

```powershell
uv run python scripts/tools/fetch_hazard_sources.py --fetch   # 原典を取得（約1.1GB・Git管理外）
uv run python scripts/tools/build_hazard_levels.py --datasets a33 a31
uv run house-search sync-hazards
uv run house-search rescore
```

- 原典は `data/hazard_sources/`（**Git 管理外**。サイズが理由で、再配布が
  禁じられているからではない）。版は同ディレクトリの `manifest.json` に
  SHA256 と取得日で記録する。
- 交差計算は約11分（A33 139,109 ＋ A31 984,403 ポリゴン × 丁目 21,388）。
  ⚠ **`--from-cache` を付けると交差計算を飛ばして集計だけやり直せる**
  （集計方法を変えるたびに11分を払わずに済む）。

## 列

| 列 | 内容 |
|---|---|
| `normalized_key` | 丁目まで（丁目の無い町は町名まで）の正規化キー |
| `level` | `chome` / `town`（町行は配下の丁目を面積で加重した値） |
| `hazard_type` | `flood`（洪水・想定最大規模） / `landslide`（土砂・警戒＋特別） / `landslide_special`（同 特別警戒のみ） |
| `area_ratio` | 丁目に占める区域の面積比（0〜1） |
| `rank_avg` | 丁目の**全面積**で加重した平均ランク（区域外を0として含む） |
| `rank_max` | 丁目内の最大ランク |

洪水のランクは浸水深（1=0.5m未満 / 2=0.5〜3m / 3=3〜5m / 4=5〜10m /
5=10〜20m / 6=20m以上）、土砂のランクは区域区分（1=警戒 / 2=特別警戒）。

## ⚠ 読むときの注意

- **`0` は「区域外だと確認した」という意味**。行が無いのは「照合できなかった」。
  この2つを混ぜると「危険なのに情報が無いから減点されない」掲載が
  「安全」と同じ扱いになる。生成側と読み込み側の双方で
  **行数の恒等式**（対象キー × 災害種別）を検査している。
- **丁目単位の評価**であり、丁目の中のどこにあるかは区別できない。
  丁目の端に少し掛かるだけでも `area_ratio` は 0 にならない。
- **`rank_avg` は上限（`rank_max`）でクリップしている。** ランクの違う区域どうしが
  地理的に重なると（土砂の警戒／特別警戒、洪水の別水系）交差面積が二重計上され、
  加重平均が上限を超える（実測で洪水 6.32・土砂 4.99）。正しくは union を取るべきだが
  100万ポリゴンでは現実的でないため、**値域だけを保証している**（過大評価は残る）。
- **原典の誤りはそのまま入ってくる。** A33 の区域区分は 1・2 のはずだが、
  実測（2026-09-05）で神奈川県に 3 が1件・4 が2件あった。生成スクリプトが
  捨てて件数を報告する。
- **位置参照情報に無い町丁も含む**（実測1,960件）。境界データの方が網羅的なため。
  住所マスタ（`m_address_points`）に載っていない町の掲載も評価できる。

## 採点での使われ方（→ [ADR 0021](../../docs/adr/0021-hazard-as-want-metric.md)）

`scan` / `rescore` は `t_listings.address_normalized` からこの表を JOIN するだけで、
**幾何ライブラリには触れない**（`tests/test_no_geo_runtime_deps.py` が固定）。

| 使いどころ | 値 |
|---|---|
| WANT（加点） | `flood_rank_avg` weight 15（best 0 / worst 4）・`landslide_area_ratio` weight 5（best 0 / worst 0.1） |
| MUST（足切り） | `flood_rank_max` / `landslide_special_ratio_max` を配線済みだが**実運用では未設定** |
| 粒度 | 丁目 → 引けなければ `m_address_points.town_key` 経由で町 |
| グループ | 名寄せしたグループ内で**最も細かい住所**を持つ掲載の値を採る |

- ⚠ **`area_ratio` は帯によって判別力が無い。** 23区は3,124丁目のうち浸水想定に
  一切掛からないのが2丁目だけで、`flood_area_ratio` は99.1%が0.25以上に固まる。
  **`rank_avg` を主力にする**（25%点0.71・中央2.0・最大4.0と階調が出る）。
- ⚠ **`rank_max` を加点に使わない。** 水路際のランク6がごく一部でも丁目全体が
  最悪扱いになる（市川市菅野5丁目は max=6 だが加重平均2.52）。足切り専用。
- **減点は実装していない。** 加点で数学的に等価で、点を差し引くと0〜100点の意味が壊れる。
