# サイト取得設計

**最終更新**: 2026-09-01（Phase 1）
**実装**: `src/house_search/scrape/`

v1 の `01_検索条件マッピング設計.md`（廃止済み）を置き換えるもの。
v2 ではサイトの検索フォームへ渡すのを**エリア・物件種別・価格上限の3つだけ**に限定し、
サイト別コードは「取得と解析」だけを担う（→ [ADR 0003](../adr/0003-local-filtering.md)）。

---

## 1. サイトへ渡す条件

| 渡すもの | 由来 | 理由 |
|---|---|---|
| エリア（都道府県・市区町村） | `search.prefectures` / `search.cities` | 母集団を絞らないと取得量が非現実的になる |
| 物件種別 | `property_type` | 賃貸と売買でURLの系統が違う |
| 価格上限 | `search.price_max_hint` | 同上。MUST上限の2〜3割増しをバッファとして渡す |

**設備条件・間取り・面積・築年数・徒歩分数はサイトへ渡さない。**
WANT条件（オートロック無しでも減点で残ってほしい）をサイト側フィルタに渡すと、
対応サイトでは物件が除外されて順位に現れず、非対応サイトでは素通りする。
ランキングを入れる以上、この2つは両立しない。

`price_max_hint` にバッファを持たせるのは、管理費を別計上するサイトで
「賃料は上限内だが管理費込みだと超える」物件を取りこぼさないため。
上限判定そのものはローカルの MUST（`rent_total_max`）で行う。

## 2. 2段判定によるコスト緩和

一覧ページに載る項目だけで MUST を先に評価し、**`fail` の掲載はDBにも入れず詳細も取りに行かない**。

```
一覧取得 → MUST(1段目) → fail なら破棄
                       → pass/unknown なら upsert → 詳細取得 → 抽出 → MUST(2段目) → 採点
```

- 1段目で判定できる項目は `MetricRegistry` の `available_on_list=True`
  （賃料・間取り・面積・築年・徒歩）
- 判定できない項目（`features` / `floor_min` / `monthly_cost_max`）は `unknown` になり、
  **`unknown` では詳細取得をスキップしない**
- 実測（2026-09-01・SUUMO 4都県）: 一覧177件 → 1段目通過22件。詳細取得を **87%削減**

詳細取得は1回の実行あたりサイト単位で上限を設ける
（既定40件 / `--full` は400件。`scrape/scan.py` の `DEFAULT_DETAIL_LIMIT`）。
取り残しは `detail_fetched_at IS NULL` のキューに残り、次回実行で拾われる。

## 4. SUUMO（Phase 1 実装済み）

### 4.1 URL

```
一覧: https://suumo.jp/jj/chintai/ichiran/FR301FC001/?ar={地方}&bs=040&ta={JIS2}&ct={万円}&sort=2&pc=30&pn={頁}
詳細: 一覧のリンク（/chintai/jnc_XXXXXXXX/?bc=YYYYYYYY）をそのまま使う
```

- `bs=040` が賃貸。`sort=2` は新着順
- `ct` は**万円単位・小数1桁**（90,000円 → `ct=9.0`）
- **`tc=`（設備条件）は送らない。** v1 は10条件を `tc=` で渡していたが v2 では全廃した
- `pc=30` が1ページの件数。これ未満しか返らなければ最終ページ

### 4.2 一覧のDOM

SUUMO は「1建物 = 複数住戸」の入れ子構造で、**住戸ごとに1掲載**になる。

| 項目 | セレクタ | 備考 |
|---|---|---|
| 建物 | `div.cassetteitem` | |
| 建物名 | `.cassetteitem_content-title` | |
| 住所 | `.cassetteitem_detail-col1` | |
| 駅情報 | `.cassetteitem_detail-text`（複数） | 徒歩分数は**最短**を採る |
| 築年・階建 | `.cassetteitem_detail-col3` | 「築40年 2階建」 |
| 住戸行 | `.js-cassette_link` | |
| 物件ID | `input[name=bc]` の `value` | URLの `bc=` と同値 |
| 所在階 | クラス無しの `td` | 「N階」に一致するセルを拾う |
| 賃料 | `.cassetteitem_price--rent` | |
| 管理費 | `.cassetteitem_price--administration` | **v1 は取得していなかった** |
| 敷金 / 礼金 | `.cassetteitem_price--deposit` / `--gratuity` | |
| 間取り / 面積 | `.cassetteitem_madori` / `.cassetteitem_menseki` | |

⚠ **管理費・敷金・礼金の「-」は「無し」を意味するので 0 として扱う。**
`None` のままにすると `rent_total`（賃料＋管理費）が「管理費不明」となり、
実際には管理費0円の物件が MUST 判定で `unknown` に落ちる。

実測の充足率（2026-09-01・49掲載）: 賃料・面積・間取り・築年・徒歩・住所・管理費・敷金・礼金
はいずれも **100%**、所在階は 100%。

### 4.3 詳細のDOM

- **設備ブロック**: `ul.inline_list` のうち**読点区切りの語が最も多いもの**を採る
  （契約期間・備考など別用途の `ul.inline_list` が混ざるため、位置では選ばない）
- **th/td の項目**: 所在地 / 駅徒歩 / 構造 / 階建 / 階 / 築年月 / 向き / 駐車場 / 入居 /
  契約期間 / 条件 / 建物種別

⚠ **構造化フィールドはアダプタ側で正規化してから `raw_features_text` に載せる。**
「駐車場: 近隣205m16500円」は語彙が無く辞書で照合できないため、
値が `-` 以外なら「駐車場あり」という派生トークンへ寄せる。
欄の意味づけ（`-` が無しを意味する 等）はサイト固有なのでアダプタが吸収し、
辞書側は語彙の対応だけを持つ。
**建物種別（アパート/マンション）は対応する条件が無く未知表記を汚すだけなので載せない**
（`type_specific_attrs` には残す）。

## 5. レート制御・robots.txt

`src/house_search/scrape/fetch.py`。設定は `m_sites` から読む。

| 項目 | 既定 | 備考 |
|---|---|---|
| リクエスト間隔 | 2.5秒 ± 30%のジッタ | `m_sites.min_interval_sec` |
| 1回の実行のページ数 | 5 | `m_sites.max_pages_per_run`（`--full` 時のみ使う） |
| 日次リクエスト上限 | なし | `m_sites.daily_request_cap` |
| リトライ | 429/5xx を最大3回・4秒から倍々 | |
| 打ち切り | 5回連続失敗でサイト中止 | `SiteAborted` |

- **robots.txt はオリジンごとに起動時1回だけ取得**し、Disallow のURLは取りに行かない
- robots.txt が取れない場合も取得は続ける（控えめな間隔は維持する）
- SUUMO の robots.txt 実測（2026-09-01）: `/jj/chintai/ichiran/FR301FC001/`（一覧）と
  `/chintai/bc_*/`（詳細。`/printout/` を除く）は `User-agent: *` に対して**許可**。
  `Crawl-delay` は bingbot にのみ 30秒の指定があり `*` には無い

## 6. 中断・再開

`t_scrape_runs` に `(run_id, mode, pattern, site, phase, cursor, status)` を記録する。
詳細取得は `detail_fetched_at IS NULL` のキュー型なので、**再開はSQLの自然な帰結**になる
（部分インデックス `ix_t_properties_detail_pending` がそのまま効く）。
upsert はすべて冪等で、二度流しても壊れない。

1. `src/house_search/scrape/{site}.py` に `SiteScraper` プロトコルを満たすクラスを書く

4. `house-search coverage`（Phase 2 で実装）で充足率を実測する

**未登録のサイトは `scan` が「スキップ（アダプタ未実装）」と明示的に報告する。**
黙って無視すると「実装済みだが未配線」を見逃すため。
