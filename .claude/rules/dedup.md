# 住所の正規化・名寄せ・住所マスタの注意

CLAUDE.md の「実装上の注意」から領域別に分けたもの（→ CLAUDE.md の表）。
実際に踏んだ落とし穴なので、該当する処理を書く・直す前に読む。

- **名寄せの住所は「丁目まで」で打ち切る。** サイトによって粒度が
  「番地まで（HOME'S）／丁目まで（多数）／町名まで（SUUMO）」とばらつき、
  番地を残すとクロスサイトの名寄せが原理的に成立しない（→ ADR 0012）
- ⚠ **丁目表記が無い住所の数字塊を、丁目と決めつけてはいけない**（→ ADR 0020・課題#48）。
  丁目が存在しない町では番地が丁目になり `埼玉県深谷市中瀬1480丁目` という
  **実在しない住所が `dedup_key` になる**（実測で掲載の5.4%）。
  ⚠ **例外にならず件数も減らない**（名寄せが静かに失敗してユニーク率が高く見えるだけ）ので、
  **外部の正典（`m_address_points`）と突き合わせるまで検出できなかった**。
  ⚠ **町がマスタに無いときは従来どおり丁目とみなす**（収録漏れを「丁目が無い」と
  読み替えると別の丁目の住戸を同一視する偽陽性になる）。
  ⚠ **小字（`早野字下夕田`）はマスタに無い**ので「字」の手前で引き直す。
  ⚠ **ただし「字」を無条件に落とさない**（小田原市 `十字四丁目` が壊れる）
- **住所マスタの正典は国土交通省の位置参照情報**（`data/address_master/`）。
  政府標準利用規約2.0 で再配布できるので**原典を Git 管理下に置く**
  （再配布不可の駅マスタ → ADR 0016 とは扱いが違う）。取得は
  `scripts/tools/fetch_address_master.py --fetch`（**CGIを辿らず直リンクで取れる**）。
  ⚠ **原典CSVは cp932**。⚠ **区分コード（1=大字/2=字/3=丁目）で丁目の実在を判定する**
  （町名の正規表現から推測しない）。⚠ **`sync-addresses` は全置換なので `id` を参照しない**
- ⚠ **`prefecture` 列を住所へ前置するのは、住所がどの都道府県でも始まらないときだけ。**
  「渡された値で始まるか」だけで判定すると、列が誤っているとき
  `長野県東京都立川市富士見町4丁目` が `dedup_key` になる（→ 課題#48）。
  ⚠ **同じタプルから来る値を片方だけ書かない**（`resolve-cities` が
  `resolve_city` の返す都道府県を捨てて city_id だけ更新していたのが元凶）。
  ⚠ **例外にも件数の減少にもならず、名寄せが静かに失敗するだけ**
- **正規化は掲載側と原典側で `normalize_base` を共用する。** 別の規則を当てると、
  突き合わせが0件になったとき「マスタに無い」のか「正規化がずれている」のかを区別できない
- **名寄せキーに建物名・築年月・総階数・賃料を入れてはいけない。** 匿名掲載
  （`ＪＲ相模線 上溝駅 2階建 築41年`）が実在し、入れると真の一致が分断される。
  面積も丸めない（丸めても一致は増えず隣接住戸を余分に潰すだけ）
- `sync_groups` は差分管理をしない**冪等な集合演算**。代表の交代・掲載の消失は
  「次の同期で自然に直る」ので、イベント駆動の張り替えを足さないこと
- **`regroup` は通知を送らない。** 既存データへの初回適用で `cheaper_listing` が
  大量発火するのを避けるため。通知は次回の `scan` の差分に任せる
- **順位はグループ代表と未グループ物件にだけ振る**（`update_ranks`）。
  `digest` は `rank_in_pattern` 起点なので、ここを崩すとランキングに重複が戻る
