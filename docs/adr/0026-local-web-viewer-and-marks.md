# ローカル限定のブラウザ閲覧画面を足し、印（お気に入り・除外・メモ）は掲載に付ける

**状態: 採用（2026-09-15・課題#68）**
**関連: 課題#68（閲覧画面）／課題#28（空のダイジェストを送らない）／課題#58（採点の徒歩は駅ごとの値）／
[ADR 0012](./0012-dedup-normalization.md)（名寄せ）／[ADR 0021](./0021-hazard-as-want-metric.md)（未解決と0を混ぜない）／
要件定義書 §4.5・§9・§11.1**

ユーザー要望（2026-09-15）: 本システムをブラウザでも見られるようにしたい。ローカル環境だけで見られればよい。

確認した要件（すべてユーザー判断）:

| 論点 | 決定 |
|---|---|
| 画面 | 検索パターン別ランキング・物件の詳細（新着履歴・運用状況の画面は作らない） |
| 書き込み | お気に入り・除外・メモ（スキャン・再採点の起動は作らない） |
| 方式 | Python のサーバ側描画 |
| 起動 | 見るときに手動で起動（常駐しない） |
| 除外の効き目 | 閲覧画面の既定表示と日次ダイジェスト（順位・採点・個別通知・成約確認は変えない） |
| 印の単位 | 同じ物件（名寄せグループ）にまとめて効かせる |
| ダイジェストの順位表示 | DB の順位のまま（欠番が見える） |
| 種別の引き継ぎ時の印 | 残す |
| サムネイル | 出さない |
| 通知へのリンク | 付けない |

---

## 決定1: Flask のサーバ側描画にする

| 候補 | 採否 | 理由 |
|---|---|---|
| **Flask＋Jinja2** | **採用** | 既存コードは同期の `Connection` で書かれており、そのまま呼べる。フォーム・テストクライアント・自動エスケープが揃い、追加依存は6個（既存パッケージのバージョンは動かない） |
| FastAPI＋Jinja2＋uvicorn | 不採用 | 追加依存の数は同じ。非同期サーバに同期の SQLAlchemy を載せることになり、`async def` に書くと**黙って全体がブロックする**罠を持ち込む |
| React 等の画面＋データ配信 | 不採用 | Node の環境・ビルド・型の二重定義が増える |
| 静的ページの書き出し | 不採用 | 絞り込みや印の書き込みができない |

- 金額・条件・交通の文言は `notify.format` の関数をそのまま使う（Discord と画面で書き方が食い違わないように）
- 順位・採点内訳は保存済みの `t_listing_scores` をそのまま表示し、**画面で採点し直さない**
- ⚠ **flask は閲覧画面だけの依存にする。** `cli._cmd_web` が遅延 import し、定期タスクの経路（scan / digest）からは
  import しない（`tests/test_web_security.py` が AST で固定）。main の `.venv` へ `uv sync` する前でも定期タスクは動く

## 決定2: 127.0.0.1 固定で待ち受け、ローカルでも3つの脅威を塞ぐ

「ローカルだけ」でも、**悪意あるサイトを開いたブラウザ**が閲覧画面を読み書きできる。

| 脅威 | 対策 |
|---|---|
| LAN からの到達 | 待ち受けは `127.0.0.1` に固定し、引数で変えられない（`--host` を持たせない） |
| DNS リバインディング | `Host` ヘッダを `127.0.0.1:<port>` / `localhost:<port>` / `[::1]:<port>` の許可リストで検証（外れたら 421）。⚠ 127.0.0.1 で待ち受けるだけでは防げない |
| CSRF | 起動ごとに作るトークンを全フォームに埋めて照合（Cookie を使わない）。`Origin` / `Sec-Fetch-Site` が付いていれば一致を求める。書き込みは POST だけ |
| XSS | Jinja2 の自動エスケープを全テンプレートで強制（`\|safe`・`Markup` はテストで禁止）。リンクにするのは http/https だけ（`safe_href`）。JavaScript を使わず CSP を `default-src 'none'; style-src 'self'; form-action 'self'` にする |
| 情報の漏洩 | テンプレートへは表示用の値だけを渡し、`Settings` を載せない。500 は定型ページで、トレースバックはログにだけ出す。デバッガ・自動リロードは使わない |

- `Referrer-Policy: no-referrer`（掲載サイトへのリンクを踏んだとき、閲覧画面の URL を送らない）
- サムネイルを出さないので、画面を開いただけで外部サイトへ画像リクエストが飛ぶことも無い

## 決定3: 閲覧は定期スキャンと排他しない

- **取得ロック（`scraping_lock`）は取らない。** 読むのは保存済みの値だけ
- 閲覧は**読み取り専用トランザクション**（`postgresql_readonly`）で行う。GET の経路で誤って書いても DB が止める
- 専用エンジンは接続数 2＋2・`statement_timeout` 10秒・`application_name=house-search-web`
  （`pg_stat_activity` で定期スキャンのロック保持と見分けられる）
- 起動は `.venv` の python を直接呼ぶ（`scripts/run_web.ps1`）。`uv run` は起動のたびに依存を同期しうるので、
  定期タスクが同じ `.venv` を使っている最中に差し替えが走らないようにする

## 決定4: 印は掲載に付け、グループへの効果は読み出し時に導く

`t_listing_marks`（`listing_id` 一意・`is_favorite`・`is_excluded`・`memo`）。

- ⚠⚠ **グループIDに付けない。** `sync_groups` はメンバー0件のグループを消し、組み直しでIDが振り直されうる。
  グループに付けると**印が例外にならずに黙って外れる**
- 「同じグループのどれか1件に印がある」の判定は `marks.mark_exists_sql` の1箇所に置き、閲覧画面の一覧と
  日次ダイジェストの双方が使う（片方だけ規則を変えると、画面では隠れているのにダイジェストに載る）
- ⚠ **チェックを外した印は、同じグループの他の掲載からも外す。** 画面はグループ全体の印を出しているので、
  外したのに別の掲載の印で残ると「外せない」ように見える
- 掲載ID（`t_listings.id`）は掲載終了・再掲載・種別の引き継ぎ（`_RETAKE`）をまたいで保たれるので、印も残る
  （引き継ぎ時に消す案はユーザー判断で採らない）
- メモは2,000字まで。⚠ 上限を超えたら**切り詰めずに**入力エラーにする（DB の CHECK 制約でも二重に守る）
- 空になった行（印もメモも無い）は消す

## 決定5: 日次ダイジェストは除外を LIMIT の前で抜く

```sql
... WHERE s.pattern_name = :name AND s.must_result <> 'fail' AND s.score IS NOT NULL
      AND NOT <mark_exists_sql('is_excluded')>
ORDER BY s.rank_in_pattern ASC LIMIT :top_n
```

- ⚠ **後から捨てない。** 後から捨てると上位 N 件が N 未満に減る。前で抜けば N が保たれ次の順位が繰り上がる
- ⚠ **順位（`rank_in_pattern`）そのものは変えない。** 表示する番号も DB の順位のまま（欠番が見える）。
  閲覧画面や個別通知の「パターン内N位」と番号を一致させる
- 飛ばした件数は `DigestResult.excluded` で返し、CLI が `（除外 N件を飛ばした）` と出す（黙って効かせない）
- 全件が除外で空になった便は、課題#28 と同じく送らない
- 変えないもの: `update_ranks`・採点・個別通知（新着・値下げ・成約・他サイト安値）・`check-sold` の対象選定

## 採らなかった案

- **除外を順位からも外す**: `update_ranks` と `rescore` に手が入り、除外を戻したときに再採点が要る
- **除外を個別通知からも外す**: スキャンの通知経路に手が入り、誤って除外したときに気づきにくい
- **常駐（ログオン時起動・サービス化）**: 使わないときもメモリを使う。サービスは System アカウントで動くので `.env` の置き場所の問題も抱える
