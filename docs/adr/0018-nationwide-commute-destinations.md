# 通勤先を地方ごとに決めて全国の駅を網羅する

**状態: 採用（2026-09-03）**
**関連: [ADR 0016](./0016-commute-time-rail-graph.md)／[ADR 0017](./0017-navitime-real-timetable.md)／課題#34**

ADR 0017 までの通勤時間は、検索パターンの `commute.destination_station`（実運用では
芝公園）ただ1つを目的地にしていた。取得対象も「いま掲載がある駅」だけで、
実測では 1,155駅グループだった。

全国の物件を扱うには、この前提が両方とも成り立たない。

- **目的地を1つに固定できない。** 北海道の駅から芝公園までの所要時間には使い道がない
- **掲載がある駅だけでは足りない。** 新しいエリアを開くたびに、その地方の駅を
  一から取り直すことになる（1駅15秒なので、後から足すほど高くつく）

---

## 決定1 … 地方ごとに中心駅を決め、その地方の駅はその駅までを採る

対応は `data/commute_destinations.yaml` を正典にする（設備抽出辞書・サイト検索
パラメータと同じ「Git管理YAMLが正典」の形）。

| 地方 | 都道府県コード | 通勤先 | 駅グループ数 |
|---|---|---|---:|
| 北海道 | 1 | 札幌 | 412 |
| 東北 | 2〜7 | 仙台 | 912 |
| 関東 | 8〜14 | 東京 | 1,898 |
| 中部 | 15〜23 | 名古屋 | 1,759 |
| 近畿 | 24〜30 | 大阪 | 1,602 |
| 中国 | 31〜35 | 広島 | 708 |
| 四国 | 36〜39 | 高松 | 479 |
| 九州・沖縄 | 40〜47 | 博多 | 996 |

⚠ **三重県は近畿に入れている**（標準的な8地方区分に従う）。名古屋通勤圏でもあるため、
実データを見て中部へ移す判断はありうる。
⚠ **沖縄県は九州と同じ博多ゆき**。鉄道が本土と繋がっていないので到達不能
（`no_route`）として記録される。事実がそのまま残るので害はない。

## 決定2 … 47都道府県の網羅を読み込み時に検証する

`load_regions` が、都道府県コードの**欠落と重複の両方**を例外にする。

⚠ **穴が開いてもエラーにならないのが怖い。** その県の駅が黙って対象外になり、
「全国を網羅したつもり」のまま気づけない。重複は逆に、同じ駅を2つの目的地で
取りにいって取得時間が倍になる。どちらも走らせてからでは遅いので読み込み時に落とす。

## 決定3 … 1コマンドで全国を回さず、地方ごとに走らせる

`fetch-commutes --region 関東` の形にした。全国8,766駅を15秒間隔で取ると
**約36.5時間**かかる。1回の実行に押し込むと、PCの再起動・ネットワークの瞬断・
サイト側の一時的な拒否のどれかで途中から進まなくなる。

地方ごとなら最長でも関東の7.9時間で、1晩に収まる。⚠ 1駅ごとにコミットするので、
地方の途中で止まっても再実行すれば続きから進む。

## 決定4 … 目的地が同じ県内で複数グループに割れていたら路線数の多いほうを採る

`resolve_station_group` は従来「一意に決まらなければ `None`」だった。

⚠ **仙台は同じ宮城県内で2グループある**（JR 4路線 / 市営地下鉄 2路線）。
駅データ.jp が乗換駅として統合していないためで、県で絞っても決まらない。
別の場所にある同名駅は都道府県で既に落ちているので、ここまで来たら
**同じ駅がグループに分かれている**とみなしてよい。路線数の多いほうを代表にする
（同数なら駅グループコードの小さいほうで固定し、実行ごとに揺れないようにする）。

⚠ **都道府県で絞れていないときの複数一致は従来どおり `None`。** そちらは
「日本橋＝東京/大阪」のような本物の同名異駅で、勝手に選んではいけない。

---

## どこまでやらないか

- **地方をまたぐ通勤は扱わない。** 熱海から東京、米原から名古屋のような越境通勤は
  実在するが、県ごとに目的地を割り当てる方式では表現できない。必要になったら
  「県 → 目的地」の粒度へ細かくする（YAMLの構造は変えずに済む）
- **中心駅は1地方1つ。** 関東で「東京・新宿・横浜」のように複数置くと取得が倍々になる。
  実運用の検索パターンは `commute.destination_station` で別途1駅を指定できるので、
  細かい通勤先はそちらで扱う
