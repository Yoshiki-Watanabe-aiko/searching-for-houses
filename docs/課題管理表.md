## #1 ABLE・SMOCCA が市区町村未指定だと0件になる

- 状態: **解決済み**（2026-09-01。SMOCCA のアダプタ自体は Phase 3）
- 内容: ABLE・SMOCCAは市区町村の指定が必須で、都道府県のみの指定では検索結果が0件になる。
- 対応履歴:
  - 2026-07-10: `docs/詳細設計書/01_検索条件マッピング設計.md`の調査で判明。
  - 2026-09-01: v2 の方針を確定。YAML の `search.cities` が空のとき、この2サイトについては
    `m_cities` から都道府県内の全市区へ自動展開する（`m_city_site_values` に行があるものが対象）。
    Phase 2（HTTP展開）で実装する。
  - 2026-09-01: Phase 2 で `src/house_search/scrape/area.py` として実装。
    アダプタが `requires_city` を宣言し、`search.cities` が空でも都道府県内の全市区へ展開する。
    対象は ABLE・SMOCCA に加え、同じく市区必須と判明した GOO・賃貸EX も含む。
    ⚠ **当初方針の「`m_city_site_values` に行があるものが対象」は撤回した。**
    この4サイトの市区の検索値は **JIS5桁コードそのもの**で `m_cities.jis_code` から導出でき、
    マッピング表に縛ると対象4都県で 67/253市区しか指定できなかった
    （東京都は23区のみで多摩地域が丸ごと漏れる）。JIS導出に切り替え、
    さらに `jis_code` 自体を実測で補完して **216/253市区**が指定できるようになった。
    残りの未登録分は課題#16。

## #13 同一サイト内で同一物件が重複掲載される

- 状態: **未解決**（Phase 4 の名寄せで対応）
- 内容: Phase 1 のダイジェスト実測で、**上位10件のうち6枠が3物件の重複**で占められた。
  クロスサイトではなく **SUUMO 単体の中**で起きている。

    住所・間取り・面積・階数・賃料がすべて一致
  - 3位/4位「ベル・グラース」: `jnc_` は同一で `bc=` が異なる（同一建物の別住戸だが仕様が同じ）

  実用上の価値が目減りする。
- 対応方針: 再設計計画 §6 の `dedup_key`（ファミリ＋正規化住所＋間取り＋面積＋階数）は
  **この事例をそのまま拾える**。Phase 4 で実装し、この3件を検証データに使う。
  ⚠ 「取り扱い店舗違いの同一住戸」と「仕様が同じ別住戸」は
  `dedup_key` では区別できないため、**後者を1件に潰してよいかは要判断**
  （潰すと選択肢が減り、残すと重複が残る）。

## #17 LIFULL HOME'S が AWS WAF のボットチャレンジを返すようになった

- 状態: **未解決**（運用しながら観測する）
- 内容: Phase 2 のアダプタ実装中、HOME'S の挙動が段階的に変わった。
  1. 既定の自己申告UA（`house-search/2.0 ...`）では **403 Forbidden**
  2. ブラウザ相当のUAに変えると 200 で取得できた（アダプタとフィクスチャはこの状態で作成）
  3. 実スキャンを重ねたのち **HTTP 202 + 空ボディ**、および
     `awsWafCookieDomainList` / `gokuProps` を含む **AWS WAF のボットチャレンジ**を返すようになった
- 判断: **チャレンジの突破は行わない。** robots.txt は当該パスを `User-agent: *` に
  許可しており、UA の選別（1・2）までは尊重の範囲と判断してサイト別UAを実装したが、
  能動的なボット検知（3）は MINIMINI の reCAPTCHA と同じ扱いにする。
- 現状の扱い: アダプタ・フィクスチャ・テストは実装済みのまま残し、`is_active=true` を維持する。
  取得できない間は `scan` が1件ずつエラーとして記録し、他サイトの処理は止まらない
  （Phase 2 で「1ページ／1物件の失敗でサイト全体を止めない」よう修正済み）。
  WAF のチャレンジはレート起因で緩む場合があるため、しばらく観測する。
- 判断が要る点: 恒常的に取得できないままなら `is_active=false` にするか要判断。
- 対応履歴:
  - 2026-09-01: Phase 2 で起票。実測の充足率は「物件6件 / 詳細4件 / 設備平均14.8件」。
    詳細2件が空ボディで落ちたため built_on と raw_features_text が 67% にとどまる。

## #18 MINIMINI の一覧ページが reCAPTCHA のボット判定下にある

- 状態: **未解決**（Phase 3 で扱いを再判断）
- 内容: MINIMINI の一覧URL（`/list/pref/{都県}/{市区スラグ}/`）へアクセスすると、
  トップ→エリア索引→市区一覧という通常の遷移順・Referer付きでも
  「ブラウザをチェックしています - reCAPTCHA」が返り、掲載を取得できない。
  robots.txt は当該パスを禁じていないが、明示的なボット対策が置かれている。
- 判断: **回避は行わない。** Phase 2 では HTTP アダプタを実装せず未実装のまま残す。
  `scan` は「スキップ（アダプタ未実装）」として明示的に報告する。
- 対応履歴:
  - 2026-09-01: Phase 2 で発見。ユーザー判断により Phase 3（Playwright 展開）で再検討する。
    ⚠ ブラウザ自動化でもボット判定の回避になる点は変わらないため、
    Phase 3 でも同じ結論になる可能性が高い。
