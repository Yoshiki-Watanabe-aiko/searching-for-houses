# アパマンショップだけ robots.txt を尊重しない

**状態: 採用（2026-09-02・Phase 3 で実施。ユーザーの明示的な判断）**
**関連: 要件定義書 §13（レート制御・robots.txt）**

アパマンショップ（`APAMAN`）の robots.txt は全パスをクローラに禁じている。

```
User-agent: *
Disallow: /
```

本プロジェクトは「robots.txt を尊重する」を方針として掲げているが、
**このサイトに限り、ユーザーの明示的な判断で取得する**。

## 経緯

Phase 3 の着手時に robots.txt を実測して全面禁止が判明し、選択肢を提示した。

| 案 | 内容 |
|---|---|
| A（提示時の推奨） | 対象外にする。`is_active=false` でアダプタを実装しない |
| B | 観測モードで実装（名指し実行のときだけ動く） |
| C | robots.txt を無視して実装 |

2026-09-01、ユーザーは **C** を選択した。方針との不整合とアクセス遮断のリスクは
提示済みで、そのうえでの判断である。

## 決定と、どこまでやらないか

`SiteFetcher.ignore_robots` を新設し、**アダプタが明示的に宣言したサイトだけ**
robots.txt の判定を飛ばす。既定は `False` で、既定を変えてはならない。

```python
class ApamanScraper:
    ignore_robots = True  # 他のサイトでこのフラグを立ててはいけない
```

**緩めるのは robots.txt の判定だけ**で、他は一切緩めない。

- 取得間隔は 4.0秒（±30%ジッタ）。他サイトの 2.5〜3.0秒より**長くしてある**
- 1回の実行のページ数上限・日次上限・429/5xx のバックオフ・連続失敗の打ち切りは
  そのまま効く
- ボット検知（CAPTCHA・WAFチャレンジ）の突破は**しない**。
  これは他サイトと同じで、この ADR の対象外である

## 帰結

- **方針の一貫性が崩れる。** 要件定義書 §13 の「robots.txt を尊重する」は
  「APAMAN を除く」という例外付きの記述になる
- **サイト側から遮断される可能性がある。** 遮断されたら `scan` がエラーとして
  記録し、他サイトの処理は止まらない
- **例外が増えないようにする。** フラグはアダプタ単位で、既定は `False`。
  新しいサイトで立てるときは、この ADR と同じくユーザーの明示的な判断を要する

## 却下した案

**フェッチャ全体で robots.txt 判定を無効化する設定を作る**: `.env` の
スイッチ1つで全サイトの尊重が消えるのは影響範囲が広すぎる。
「どのサイトが例外なのか」がコードから読み取れなくなる点も悪い。
