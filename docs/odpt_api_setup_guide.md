# ODPT API トークン取得手順

**作成日**: 2026-09-03（Phase 5D 第0歩）
**目的**: 通勤時間を実ダイヤから算出するため、公共交通オープンデータセンター（ODPT）の
鉄道時刻表を取得できるようにする。

| 項目 | 内容 |
|---|---|
| サービス | 公共交通オープンデータセンター <https://www.odpt.org/> |
| 開発者サイト | <https://developer.odpt.org/> |
| 費用 | **無料**（利用者登録が必要） |
| 難易度 | 低（メールアドレスでの登録とトークン発行のみ） |
| 取得するもの | アクセストークン（consumerKey）1本 |
| 保存先 | `.env` の `ODPT_CONSUMER_KEY` |
| 有効期限 | 不明（登録時に確認する。失効したら再発行して `.env` を差し替える） |

---

## 手順

⚠ **開発者サイトは JavaScript 必須の SPA** で、`curl` では画面を読めない。
そのため以下は大枠のみで、画面の項目名は実物に合わせて読み替えること。

1. <https://developer.odpt.org/> をブラウザで開く
2. 利用者登録する（メールアドレス・パスワード）
3. **公共交通オープンデータ基本ライセンス**に同意する
4. ログイン後、アクセストークン（consumerKey）を発行する
5. 発行されたトークンを `.env` へ転記する

```
ODPT_CONSUMER_KEY=（発行された値）
```

⚠ **トークンをチャットに貼らない。** チャット履歴は平文で残る。
`.env` へ直接転記すること（ENV規約）。`.env` は `.gitignore` 済み。

---

## 登録時にあわせて確認すること

| # | 確認内容 | なぜ要るか |
|---|---|---|
| 1 | **列車時刻表が恒常提供か、「公共交通オープンデータチャレンジ」の期間限定データか** | 期間限定だと Phase 5D 第2段（8:30着の逆探索）の前提が崩れる |
| 2 | **東京メトロが同じトークン・同じホストで取れるか** | メトロは以前は別サイト（developer.tokyometroapp.jp）で提供されていた経緯がある |
| 3 | APIのアクセス頻度制限の記載 | 取得スクリプトの間隔（既定2秒）を合わせる |

## 疎通確認

トークンを `.env` へ入れたら、調査用スクリプトで実レスポンスを取る。

```powershell
uv run python scripts/tools/odpt_spike.py --operator Toei
```

⚠ PowerShell 5.1 では `&&` によるコマンド連結が使えない。1行ずつ実行すること。

このスクリプトは**取得できていないのに正常終了しない**ように書いてある
（0件・配列でない応答・全ホスト失敗はいずれもエラーで落とす）。
このプロジェクトは「HTTP 200 のまま中身が空」で気づけない事故を
4回踏んでいるため（SUUMOのエラーページ・ATHOMEの認証ページ・課題#29の無効パラメータ・
Google Routes API の空応答）、疎通確認の段階から件数を必ず目で見る。

出力される内容:

- 応答したホスト（`api.odpt.org` か `api-tokyochallenge.odpt.org` か）
- 路線・駅・列車時刻表・駅時刻表それぞれの**キーごとの充足率**（任意項目の欠落を見る）
- `odpt:calendar` / `odpt:trainType` の値の分布
- **連続する2停車から区間を何件取り出せたか**（ここが0なら第1段は成立しない）

生データは `data/odpt/raw/{事業者}/` へ保存される（Git管理外 →
[`data/odpt/README.md`](../data/odpt/README.md)）。
