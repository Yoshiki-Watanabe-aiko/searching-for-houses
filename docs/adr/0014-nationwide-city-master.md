# 市区町村マスタの正典を総務省コード表へ移し、全国を網羅する

**状態: 採用（2026-09-03・Phase 5A）**
**関連: ADR 0009（縦持ち転換）を補強／要件定義書 §11.2／課題#16・#21**

`m_cities` は2つの役割を持つ。YAML の `search.cities` に書く値の正典であり、
市区必須サイトの検索URLを組み立てる **JIS5桁コードの供給源**でもある。
つまりこの表の欠落と誤りは「その市区が丸ごと検索対象から漏れる」
「**別の市区の一覧を叩く**」に直結する。

初版は v1 の `cities` テーブルを引き継ぎ、Phase 2 でエイブルのエリア索引から
実測補完したものだった。実測してみるとこれが二重に壊れていた。

---

## 何が壊れていたか

### 1. 15都道府県しか無かった

| 項目 | 実測（2026-09-03 適用前） |
|---|---|
| 行数 | 947 |
| 都道府県 | **15**（47中） |
| `jis_code` 非NULL | 631 / 947 |

対象4都県（東京・千葉・埼玉・神奈川）253市区のうち指定できるのは216件で、
残り37市区は市区必須サイトの検索対象から落ちていた（課題#16）。
対象エリアを1県でも広げると、その県は丸ごと使えない。

### 2. 他市のコードが混入していた

補完を**部分文字列一致**で行ったため、5件の誤りが入っていた。

| 都道府県 | 市区 | 誤 | 正 | 原因 |
|---|---|---|---|---|
| 愛知県 | 名古屋市 | `23234` | `23100` | **北名古屋市**のコード |
| 大阪府 | 大阪市 | `27227` | `27100` | **東大阪市**のコード |
| 静岡県 | 浜松市中央区 | `22131` | `22138` | 2024年の区再編（7区→3区）に |
| 静岡県 | 浜松市浜名区 | `22132` | `22139` | 追随しておらず、新しい区名に |
| 静岡県 | 浜松市天竜区 | `22133` | `22140` | 旧区のコードが付いていた |

⚠ **前2件は「同じコードを持つ行が2つある」状態だった**（名古屋市と北名古屋市が
ともに `23234`）。JIS系サイトでは、どちらの市を指定しても北名古屋市の一覧が返る。
**取得は成功し、掲載も返り、エラーにもならない。**
エリア帯を愛知・大阪へ広げていたら気づけないまま誤ったデータが積もっていた。

## 決定

### 決定1: 正典を総務省「全国地方公共団体コード」にする

- 出典: <https://www.soumu.go.jp/denshijiti/code.html>（基準日 2024-01-01）
- ライセンス: 政府標準利用規約。出典明示のうえ商用利用・改変可
- **原典CSVを `data/city_master/` に Git 管理下で置く。** Excel はバイナリで差分が
  読めず、配布URLは改訂のたびに変わる。取得済みのCSVを版として残さないと
  「いつ時点のコード表で生成したマスタか」を後から言えなくなる
- `db/seed/06_cities.sql` は `scripts/tools/generate_city_seed.py` の**生成物**にする

結果は **1,918行 / 47都道府県 / `jis_code` 100%**。
内訳は市区町村1,747（一般に言う1,718市町村＋東京23区＋北方領土6村）＋
政令指定都市の行政区171。

**サイトのエリア索引から実測する方式をやめる**のがこの決定の要点である。
実測は「そのサイトが扱う市区しか集まらない」うえに、名前の部分一致で
他市のコードを拾う。行政区画のコードは政府が配っているのだから、
**サイトから推定するのが誤りだった**。

⚠ ただし**サイト固有スラグ**（HOMES / ATHOME / NIFTY / MINIMINI）は
JIS から導出できないので、引き続き各サイトのエリア索引から集めるしかない
（`m_city_site_values`。課題#21）。JIS系6サイトだけがこの決定で全国化される。

### 決定2: 既存行の `canonical_name` は変えない

`canonical_name` は YAML の `search.cities` から参照され、`t_listings.city_id` の
FK でもある。総務省表記へ機械的に寄せると、YAML の記述が黙って解決できなくなる。

幸い**既存947行はすべて総務省表記と一文字違わず一致した**（表記ゆれ0件）ため、
実際には衝突しなかった。それでも規則としては「既存の正規名を変えない」を採る。
表記ゆれは**マスタ側ではなく照合側**（`normalize_city_key`）で吸収する。

⚠ 過去に起きた「鎌ヶ谷市／鎌ケ谷市」の事故（→ 課題#24）はマスタの問題では
なかった。マスタもYAMLも総務省表記の「鎌ケ谷市」で正しく、**サイトが返す住所**が
小書きの「鎌ヶ谷市」だったために city_id が NULL に落ちていた。
直す場所は解決側である。

### 決定3: `jis_code` に部分ユニーク索引を張る

`uq_m_cities_jis_code`（`WHERE jis_code IS NOT NULL`）。
コードの重複は「別の市区の一覧を叩く」という**沈黙する誤り**を生むので、
DB側で弾く。NULL を許したまま一意にしたいので部分索引にする
（総務省一覧に無い自治体の行を残せるようにするため）。

⚠ 索引を張る前に誤コードを訂正しないと、索引の作成そのものが失敗する。
マイグレーションは訂正 → 索引作成の順で書く。

### 決定4: 政令指定都市は市と行政区の両方を持ち、展開時に親を外す

サイトによって指定できる粒度が違うので両方が要る。ただし取得URLを組み立てる
ときは、**行政区を持つ市の親行を必ず外す**。外さないと横浜市（`14100`）と
横浜市西区（`14103`）の両方を叩き、同じ掲載を二重に取得する。

あわせて `search.cities` に市名だけを書いたら、その市の**行政区へ展開する**。
「横浜市」と指定したときに市そのものを送るか区を送るかはサイトごとに違って
確かめようがないので、`m_city_site_values` にも登録があり確実に引ける区へ寄せる。

### 決定5: 都道府県を前置しない住所は「検索範囲の中で一意な名前」で引く

全国化すると全国一意な市区名は **1,861 / 1,918** まで減る。
「府中市」（東京都・広島県）「伊達市」（北海道・福島県）のような衝突が生まれ、
賃貸EX のように都道府県を書かない住所（`足立区竹の塚６`）が引けなくなる。

`CityIndex` を導入し、**検索パターンが対象にしている都道府県の中でだけ**
一意性を判定する。パターンの範囲内なら「府中市」は一意なので引き当てられる。
都道府県を前置した住所は従来どおり全国から引く（対象外の県の掲載がサイトから
返ってくることは普通にあり、落とす理由がない）。

実測では全国化による解決の劣化は **10,322掲載中1件だけ**
（`府中市白糸台２`・SMOCCA）で、逆に新たに10件が解決できるようになった。
1件のためだけの仕組みに見えるが、**対象エリアを広げるほど効く**。

## 代替案と、採らなかった理由

| 案 | 却下理由 |
|---|---|
| e-Stat 標準地域コードAPI | 同じデータだがAPI依存になる。オフラインで完結させたい |
| 国土数値情報 行政区域データ（N03） | ポリゴン付きで過剰。コード表としては重い |
| 対象4都県＋隣接県だけ整備 | 作業量は減るが「網羅」にならず、エリアを広げるたびに同じ作業が再発する |
| 既存947行を全部作り直す（`canonical_name` も総務省表記へ） | YAML の参照と `t_listings.city_id` を壊しうる。今回は表記ゆれ0件で不要だった |
| 廃置分合で消えた自治体の行を削除する | `t_listings.city_id` から参照されている可能性がある。**削除しない**（今回は該当0件） |

## 影響

- `m_cities`: 947 → **1,918行**（47都道府県・`jis_code` 100%）
- 既存掲載の `city_id` 解決率: 10,312 / 10,322 → **10,322 / 10,322（100%）**
  （`resolve-cities` で16件を引き直した）
- 帯の採点は不変（両方の帯で採点される掲載0件・上位10件の市区はすべて帯内）
- JIS系6サイト（SUUMO/GOO/ABLE/賃貸EX/EHEYA/SMOCCA）は**全国どの市区でも
  検索URLを組み立てられる**ようになった。エリア帯を広げるときにマスタが
  ボトルネックにならない

## 残る課題

- **サイト固有スラグは全国化していない**（HOMES 158 / ATHOME 78 / NIFTY 824 /
  MINIMINI 158行）。ATHOME はボット検知が発動中で収集できない（課題#20・#21）
- 総務省コード表の改訂追随は手動（`--fetch` の定数更新）。
  市町村合併はほぼ止まっているため、当面は問題にならない
