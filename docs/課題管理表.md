## #1 ABLE・SMOCCA が市区町村未指定だと0件になる

- 状態: **解決済み**（2026-09-01。SMOCCA のアダプタ自体は Phase 3）
- 内容: ABLE・SMOCCAは市区町村の指定が必須で、都道府県のみの指定では検索結果が0件になる。
- 対応履歴:
  - 2026-07-10: `docs/詳細設計書/01_検索条件マッピング設計.md`の調査で判明。
  - 2026-09-01: v2 の方針を確定。YAML の `search.cities` が空のとき、この2サイトについては
    `m_cities` から都道府県内の全市区へ自動展開する（`m_city_site_values` に行があるものが対象）。
    Phase 2（HTTP展開）で実装する。
  - 2026-09-01: Phase 2 で `src/house_search/scrape/area.py` として実装。
    アダプタが `requires_city` を宣言し、`search.cities` が空でも都道府県内の全市区へ展開する。
    対象は ABLE・SMOCCA に加え、同じく市区必須と判明した GOO・賃貸EX も含む。
    ⚠ **当初方針の「`m_city_site_values` に行があるものが対象」は撤回した。**
    この4サイトの市区の検索値は **JIS5桁コードそのもの**で `m_cities.jis_code` から導出でき、
    マッピング表に縛ると対象4都県で 67/253市区しか指定できなかった
    （東京都は23区のみで多摩地域が丸ごと漏れる）。JIS導出に切り替え、
    さらに `jis_code` 自体を実測で補完して **216/253市区**が指定できるようになった。
    残りの未登録分は課題#16。
  - 2026-09-02: Phase 3 で市区必須のサイトが増えた。実測の結果、
    **NIFTY・APAMAN・SMOCCA も都道府県ページには掲載が載らない**（エリア索引になる）。
    NIFTY はサイト固有スラグ（`adachiku`）なので `m_city_site_values` を引き、
    APAMAN は **JIS5桁の下3桁**（13121 → `121`）、SMOCCA は JIS5桁をそのまま使う。
    ATHOME・EHEYA は都道府県ページでも掲載が返るため `requires_city=False`。

## #5 「賃貸EX」サイトの追加対応要否が未決定

- 状態: **解決済み**（2026-09-02・Phase 5 で本採用）
- 対応履歴:
  - 2026-07-10: 発見・記録。ユーザー判断待ち。
  - 2026-09-01: **対応する**方針で確定。`CHINTAI_EX` として `m_sites` に登録済み
    （`is_active=false`）。Phase 2 で base_url・エリア指定方式を確定し、
    観測モードでユニーク物件率を実測してから通知を有効化する。
  - 2026-09-01: Phase 2 で調査・実装完了。`base_url=https://chintai-ex.jp`、
    市区一覧は `/search/city/{JIS5}`、ページ送りは `/page/{N}` の**パス形式**。
    ⚠ **robots.txt が `Disallow: *?*` でクエリ付きURLを全面的に禁じている**ため
    価格上限をサイト側へ渡せず、市区の全掲載を取ってローカル判定する。
    ⚠ **同じURLでも一覧レイアウトが3通り返る**（実測）ので、
    `parse_list` はタグではなくクラス（`js-bukken`）で拾って中身で分岐する。
    `is_active=false` のまま観測モードで運用し、
    `scan --site CHINTAI_EX --seed` と名指ししたときだけ動く。
    実測（足立区・葛飾区・八王子市の各1ページ）: 一覧175件・詳細11件・設備平均12.9件。
    ユニーク物件率は Phase 4 の名寄せで測る。説明文の扱いは課題#19。
  - 2026-09-02: Phase 4 で**ユニーク率91%**を実測（11掲載中10件がユニーク。
    他サイトと一致したのは `モント竹ノ塚`＝スモッカとの1件のみ）。
    ⚠ **サンプル11掲載は少なすぎる**ので本採用の判断はまだできない。
    Phase 5 の初回全件スキャン後に `dedup-stats` で測り直して決める。
    説明文の扱い（課題#19）は先に解決した。
  - 2026-09-02: **Phase 5 で本採用した**（`is_active=true`）。初回全件スキャン
    8,429掲載で測り直した結果、**全体のユニーク率は26%**（850掲載中627件が
    他サイトと重複）まで落ちた。ここだけ見ると不採用に見えるが、
    **エリア帯を都心45分圏に絞ると63%・69代表**と GOO（127代表）に迫る寄与になる。
    全体の26%は216市区を舐めて市区必須サイト（ABLE・APAMAN・GOO・SMOCCA）と
    重なった結果であり、通勤圏では独自性がある（→ ADR 0013）。
    ⚠ あわせて `max_pages_per_run` を 50 → 5 に下げた。観測モードでは
    「市区の全掲載を取る」前提だったが、エリア帯で86市区へ絞ったので
    5ページ（1市区100件）で足りる。50のままだと `--full` で 86×50=4,300ページになり
    **賃貸EXだけで3.6時間**かかる。

## #13 同一サイト内で同一物件が重複掲載される

- 状態: **解決済み**（2026-09-02・Phase 4）
- 内容: Phase 1 のダイジェスト実測で、**上位10件のうち6枠が3物件の重複**で占められた。
  クロスサイトではなく **SUUMO 単体の中**で起きている。
  - 1位/2位「フレンズハイツ」: `jnc_` が異なる別ページ（取り扱い店舗違い）。
    住所・間取り・面積・階数・賃料がすべて一致
  - 3位/4位「ベル・グラース」: `jnc_` は同一で `bc=` が異なる（同一建物の別住戸だが仕様が同じ）
- 影響: ランキングの上位枠が実質的に減る。Phase 1 の完了条件自体は満たすが、
  実用上の価値が目減りする。
- 対応方針: 再設計計画 §6 の `dedup_key`（ファミリ＋正規化住所＋間取り＋面積＋階数）は
  **この事例をそのまま拾える**。Phase 4 で実装し、この3件を検証データに使う。
  ⚠ 「取り扱い店舗違いの同一住戸」と「仕様が同じ別住戸」は
  `dedup_key` では区別できないため、**後者を1件に潰してよいかは要判断**
  （潰すと選択肢が減り、残すと重複が残る）。
- 対応履歴:

## #25 リトライ対象外の4xxで「連続失敗による打ち切り」が発火しない

- 状態: **解決済み**（2026-09-02・Phase 5）
- 内容: `SiteFetcher.get` は 405・403 のような非リトライ4xxで
  `raise_for_status()` がそのまま例外を投げ、**その下の `failures` /
  `consecutive_failures` の加算に到達していなかった**。
  このため要件定義書 §13 が謳う「連続失敗でサイト打ち切り」が永久に発火せず、
  初回全件スキャンで **NIFTY の 405 を271回叩き続けた**
  （5時間43分のエラー555行のうち542行が NIFTY）。
- ⚠ **連鎖したデッドコード**: 404 も同じ経路で例外になるため、
  `suumo.py` の `response.status_code == 404` による成約判定に**到達できなかった**。
  直前の `except Exception: return False`（判定保留）に吸われるため、
  **404 を返す掲載は永久に `active` のまま残る**。
- 対応: 404 は例外にせず `response` を返し（呼び出し側が判定する）、
  403・405 などの拒否系は `failures` に数えて5回連続で `SiteAborted` にする。
  `tests/test_fetch.py` に4件の回帰テストを追加した。
- ⚠ **NIFTY の405は恒久的な仕様ではなかった。** 1リクエストだけ実測したところ
  既定UA・Referer無しでも 200 で取得できた（2026-09-02）。
  短時間の連続アクセスに対する一時的な制限とみられる。
  相手が拒否しているのに手を引けないことが問題であって、405 自体ではない。
- 対応履歴:
  - 2026-09-02: 初回スキャンのエラー集計から発覚・起票・同日対応。

  - ABLE・賃貸EX・APAMAN・EHEYA・NIFTY・SMOCCA: そもそも上限を渡さない

  実測したから気づけたが、仕組みとしては何も検出しない。
  対応方針の候補: (a) `scan` が「詳細取得済みの掲載があるのに一覧0件」の
  サイトを警告する / (b) 一覧0件が2回続いたらエラーチャンネルへ通知する
