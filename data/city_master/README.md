# 市区町村マスタの原典

`m_cities`（YAML の `search.cities` に書く値の正典）を生成するための原典データ。

## soumu_local_gov_codes.csv

| 項目 | 内容 |
|---|---|
| 出典 | 総務省「全国地方公共団体コード」 <https://www.soumu.go.jp/denshijiti/code.html> |
| 原本 | `000925835.xlsx`（団体コード表） |
| 基準日 | 2024-01-01（シート名「R6.1.1現在の団体」） |
| 取得日 | 2026-09-03 |
| ライセンス | 政府標準利用規約（第2.0版）。出典明示のうえ商用利用・改変可 |
| 行数 | 1,918行 = 市区町村1,747 ＋ 政令指定都市の行政区171。47都道府県 |

市区町村1,747の内訳は、一般に言う「1,718市町村」＋東京23区＋北方領土6村。

### 列

| 列 | 内容 |
|---|---|
| `jis_code` | 全国地方公共団体コードの上位5桁（検査数字を除いたもの） |
| `prefecture` | 都道府県名 |
| `city_name` | 区市町村名。政令市の行政区は市名を除いた部分（例: `西区`） |
| `parent_city` | 政令指定都市名（例: `横浜市`）。一般市町村・特別区は空 |
| `canonical_name` | YAML に書く正規名。同一都道府県内で一意 |

### 更新のしかた

**CSV も SQL も生成物なので手で編集しない。**

```powershell
uv run python scripts/tools/generate_city_seed.py --fetch
uv run python scripts/tools/generate_city_seed.py --report
```

`--fetch` は総務省のExcelを取り直して CSV と `db/seed/06_cities.sql` を作り直す。
`--report` は書き込まずにDBの現状との差分だけを出す。

⚠ **総務省の配布ファイル名は改訂のたびに変わる。** `--fetch` はページを解析せず
`generate_city_seed.py` の `SOURCE_XLSX` を直接叩くので、改訂時は定数と
`SOURCE_AS_OF`・`SHEET_*` を更新すること。

### なぜCSVをGit管理するか

Excel はバイナリで差分が読めず、配布URLは改訂のたびに変わる。取得済みのCSVを
版として残さないと「いつ時点のコード表で生成したマスタか」を後から言えなくなる。
政府標準利用規約は再配布を認めているので、原典そのものを置いてよい。

### 既知の特記事項

- **北海道の「泊村」だけが同一都道府県内で衝突する。** 後志総合振興局 古宇郡泊村
  （`01403`）と根室振興局 国後郡泊村（`01696`）。政令市の区を市名で prefix するのと
  同じ考え方で、北方領土側を `国後郡泊村` として区別している
  （`generate_city_seed.py` の `CANONICAL_OVERRIDES`）
- **政令指定都市は親の市と行政区の両方を持つ。** サイトによって指定できる粒度が
  違うため両方が要る。ただし検索URLを組み立てるときは、区を持つ市の親行を
  展開対象から外さないと市と区で二重に取得することになる
  （`scrape/area.py`）
